## E2B sandbox

`factory/sandbox.ts`

| Wave | Provider |
|---|---|
| 0 | Host worktree |
| 1–2 | E2B (Daytona allowed as alternate image) |

Lifecycle: create → shallow clone → test command → harvest patch → destroy.

Hard rules:

- No GitHub App private key in the box.
- No SSH keys, npm tokens, or `.env`.
- Network allowlist: git + package registries.
- If tests cannot run, park. Do not skip the oracle.
- Dry-run in this repo is labeled `dry-run`. It does not stamp `harvested` with exit 0.

Wire `E2B_API_KEY` in the worker host (not this git tree) to make it live.

### Witnessed evidence (issue #6)

`factory/witness.ts` executes the evidence protocol instead of accepting operator claims: clone,
tests green at `head`, revert the non-test production files to `base`, tests must go red. The CLI's
`evidence` command runs it (host runner, Wave 0 only per ADR 0003) and the manifest carries a
`witness` block — provider, both exit codes, sha256 of both logs, the repo and range it was
produced for, and the paths where those logs were written. `evidenceIsReady` refuses manifests
without one, so `draft-ready` is unreachable on attested exits. E2B/Daytona targets refuse in this
CLI: without `E2B_API_KEY` the refusal says "cannot witness evidence in dry-run"; with it,
execution still belongs to the worker host — this repo never fakes a green harvest.

### Ingesting a worker-host witness (issues #35, #36)

The runner that executes on the worker host is deliberately not in this tree (ADR 0003). What is in
this tree is the honest way to get its result **in**: `foundry attach-witness <packetId> --manifest
<path>`. The manifest is the witness block plus the `testCommand` that produced it. On ingest the
CLI re-checks, in this order, and refuses rather than degrading:

1. the manifest parses and carries a subject (`repoId`, `baseSha`, `headSha`) and both log paths;
2. the `testCommand` is the repo's own oracle, not some other command;
3. both log hashes recompute from the logs on disk (`verifyWitnessLogs`);
4. the range is real, fast-forward, and within the repo's caps (`compareCommits`);
5. the state machine accepts the provenance — `host` only on a Wave-0 host repo, `e2b`/`daytona`
   only matching the repo's `sandbox` — and the subject matches the packet.

Without this verb the only way past the Wave-1 refusal was to hand-write a witness block into
`.foundry-state.json`, which is the evidence-fabrication the doctrine exists to prevent. Wave 1 is
operable end to end through the ingest verb; it is the worker-host runner, not the pipeline, that
lives elsewhere.

## Scorecard halt

`factory/scorecard.ts`, consulted by `factory/engine.ts`.

Halt a repo (`stop`) when:

- maintainer tone is `banned`, or
- any revert of our patch, or
- opened ≥ 3, at least one terminal outcome, and merge rate < 40% (merge rate = merged / terminal outcomes; silence alone never halts).

Watch when tone is `cold`, or opened ≥ 2 and merge rate < 60% (no silence guard by design — soft caution).

A `stop` repo is unselectable until a human removes the halt in `allowlist.yaml`.

## GitHub App (operator host)

Permissions (least):

- Contents: read on upstream, write on operator forks.
- Pull requests: write (draft).
- Issues: read.
- Checks: read.
- Metadata: read.

No administration. No merge. No Actions write on upstream.

The App is **not** installed on ColeMurray/background-agents. `POST /pulls` there is 403. The in-repo create helper still hard-codes `draft: true` and exposes no merge method.

## Promotion rule

v2 features may run on Wave 0 immediately. They may run on Wave 1 after **two merged Wave 0 packets** in this factory with `humanAttest` (orca-fleet#70 and #72). Historical oss-contribute does not increment that counter.
