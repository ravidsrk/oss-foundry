# v2 — scout, sandbox, scorecard

v2 is adapters in `factory/`. Credentials stay out of git. Grok scout overlay is not shipped.

## Live GitHub scout

`factory/github-scout.ts` — user-initiated fetch of open issues on Wave 0–1 allowlisted repos. Public GitHub API; `GITHUB_TOKEN` / `GH_TOKEN` on the operator host raises the rate limit. Never on page load. Queueing still obeys one-in-flight, halt, and the Wave 1 promotion gate.

## E2B sandbox

`factory/sandbox.ts`

| Wave | Provider |
|---|---|
| 0 | Host worktree |
| 1–2 | E2B (Daytona allowed as alternate image) |

Lifecycle: create → shallow clone → test command → harvest patch → destroy.

Hard rules:

- No GitHub App private key in the box.
- No SSH keys, npm tokens, or `.env`.
- Network allowlist: git + package registries.
- If tests cannot run, park. Do not skip the oracle.
- Dry-run in this repo is labeled `dry-run`. It does not stamp `harvested` with exit 0.

Wire `E2B_API_KEY` in the worker host (not this git tree) to make it live.

## Scorecard halt

`factory/scorecard.ts`, consulted by `factory/engine.ts`.

Halt a repo (`stop`) when:

- maintainer tone is `banned`, or
- any revert of our patch, or
- opened ≥ 3 and merge rate < 40%.

Watch when tone is `cold`, or opened ≥ 2 and merge rate < 60%.

A `stop` repo is unselectable until a human removes the halt in `allowlist.yaml`.

## GitHub App (operator host)

Permissions (least):

- Contents: read on upstream, write on operator forks.
- Pull requests: write (draft).
- Issues: read.
- Checks: read.
- Metadata: read.

No administration. No merge. No Actions write on upstream.

The App is **not** installed on ColeMurray/background-agents. `POST /pulls` there is 403. The in-repo create helper still hard-codes `draft: true` and exposes no merge method.

## Promotion rule

v2 features may run on Wave 0 immediately. They may run on Wave 1 after **two merged Wave 0 packets** in this factory with `humanAttest` (orca-fleet#70 and #72). Historical oss-contribute does not increment that counter.
