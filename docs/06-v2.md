# v2 — scout, sandbox, scorecard

v2 is adapters in `factory/`. Credentials stay out of git. Grok scout overlay is not shipped.

## Live GitHub scout

`factory/github-scout.ts` — user-initiated fetch of open issues on Wave 0–1 allowlisted repos. Public GitHub API; `GITHUB_TOKEN` / `GH_TOKEN` on the operator host raises the rate limit. Never on page load.

**Not wired into `cli.ts`, and on no live path.** `tick` runs through `tickWithGithub`, which walks each repo's *named* `firstIssues` instead of discovering issues — "the factory will not invent work" is the doctrine `applyTick`'s idle branch enforces. This module is the discovery half of that seam, deliberately unwired, so there is no queueing path behind it: one-in-flight is `hasInflight`, which `applyTick` and `applyQueueLive` check themselves, while the platform halt, the denylist, the roster, the scorecard stop and the Wave 1 promotion gate are `maySelectRepo` — called directly by `applyQueueLive` and reached by `applyTick` through `pickCandidate` — and all of it applies to what those two functions are handed. Wiring discovery in therefore means routing it through them **and** through `classifyCompetition` first — the module returns ranked issues with no competing-work check, so feeding its output straight in would scout over a maintainer's open PR (`factory/github-scout.ts`).

## E2B sandbox

`factory/sandbox.ts`

| Wave | Provider |
|---|---|
| 0 | Host worktree |
| 1–2 | E2B, or Daytona where the repo's own `allowlist.yaml` entry names it |

ADR 0003 allows either provider at Wave 1+; the choice is per repo, made by that repo's `sandbox:`
field, and the witness gate holds each repo to the one its entry names (`witnessProvenanceViolation`
— see docs/10-schemas.md). Every Wave 1–2 entry currently reads `sandbox: e2b`, so a `daytona`
witness is refused everywhere on today's allowlist; making one legal means editing the entry, not
the gate.

Lifecycle: create → shallow clone → test command → harvest patch → destroy.

Hard rules:

- No GitHub App private key in the box.
- No SSH keys, npm tokens, or `.env`.
- Network allowlist: git + package registries.
- If tests cannot run, park. Do not skip the oracle.
- Dry-run in this repo is labeled `dry-run`. It does not stamp `harvested` with exit 0.

Wire `E2B_API_KEY` in the worker host (not this git tree) to make it live.

### Witnessed evidence (issue #6)

`factory/witness.ts` executes the evidence protocol instead of accepting operator claims: clone,
tests green at `head`, revert the non-test production files to `base`, tests must go red. The CLI's
`evidence` command runs it (host runner, Wave 0 only per ADR 0003) and the manifest carries a
`witness` block — provider, both exit codes, sha256 of both logs, the repo and range it was
produced for, and the paths where those logs were written. `evidenceIsReady` refuses manifests
without one, so `draft-ready` is unreachable on attested exits. E2B/Daytona targets refuse in this
CLI: without `E2B_API_KEY` the refusal says "cannot witness evidence in dry-run"; with it,
execution still belongs to the worker host — this repo never fakes a green harvest.

### Ingesting a worker-host witness (issues #35, #36)

ADR 0003 puts the *execution* of an untrusted clone on the worker host rather than here. Where the
runner's **source** lives is not an ADR question and no ADR decides it: keeping it out of this tree
is an operational choice, so this repo stays the control plane and ships nothing that could be
mistaken for a sandbox. What is in this tree is the honest way to get the runner's result **in**:

```
node --experimental-strip-types factory/cli.ts attach-witness <packetId> --manifest <path>
```

The manifest is the witness block plus the `testCommand` that produced it. On ingest the CLI
re-checks, in this order, and refuses rather than degrading:

1. the manifest parses, carries a subject (`repoId`, `baseSha`, `headSha`), and names this packet's
   own log paths — `docs/evidence/logs/<packetId>/{test,revert}.log` and nothing else, so an
   operator-supplied file cannot send the next step reading `../../../../etc/passwd`;
2. the `testCommand` is the repo's own oracle, not some other command;
3. both log hashes recompute from the logs on disk (`verifyWitnessLogs`);
4. the range is real, fast-forward, and within the repo's caps (`compareCommits`);
5. the state machine accepts the provenance — `host` only on a Wave-0 host repo, `e2b`/`daytona`
   only matching the repo's declared `sandbox` — and the subject, log paths included, matches the
   packet.

Without this verb the only way past the Wave-1 refusal was to hand-write a witness block into
`.foundry-state.json`, which is the evidence-fabrication the doctrine exists to prevent. Wave 1 is
operable end to end through the ingest verb; it is the worker-host runner, not the pipeline, that
lives elsewhere.

## Scorecard halt

`factory/scorecard.ts`, consulted by `factory/engine.ts`.

Halt a repo (`stop`) when:

- maintainer tone is `banned`, or
- any revert of our patch, or
- opened ≥ 3, at least one terminal outcome, and merge rate < 40% (merge rate = merged / terminal outcomes; silence alone never halts).

Watch when tone is `cold`, or opened ≥ 2 and merge rate < 60% (no silence guard by design — soft caution).

A `stop` repo is unselectable until a human edits the scorecard row that holds the stop (live state, and
`factory/seed.ts` for the published one) — not `allowlist.yaml`, whose roster is what the scorecard rows
are built from.

## GitHub App (operator host)

Permissions (least):

- Contents: read on upstream, write on operator forks.
- Pull requests: write (draft).
- Issues: read.
- Checks: read.
- Metadata: read.

No administration. No merge. No Actions write on upstream.

The App is **not** installed on ColeMurray/background-agents. `POST /pulls` there is 403. The in-repo create helper still hard-codes `draft: true` and exposes no merge method.

## Promotion rule

v2 features may run on Wave 0 immediately. They may run on Wave 1 after **two merged Wave 0 packets** in this factory with `humanAttest` (orca-fleet#70 and #72). Historical oss-contribute does not increment that counter.
